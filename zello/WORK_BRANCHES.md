# 이슈 번호로 작업 시작

로그인 후 **팀 작업 / 내 작업 → 작업 상세 → 작업 시작**에서 GitHub에 `feat/{GitHub 이슈 번호}` 브랜치를 준비한다. 예: `#23` → `feat/23`. 로컬 전용 이슈는 GitHub 발행 후 시작한다. 저장하지 않은 수정은 먼저 저장하며 보관·완료한 작업은 다시 열고 시작한다.

- `GET /api/projects/{projectId}/issues/{issueId}/branch`: 현재 GitHub 저장소 접근을 재검증하고 작업 브랜치 계획 또는 저장한 브랜치와 명령어를 조회한다. GET으로 브랜치를 만들지 않는다.
- `POST` 같은 경로: `{version}`으로 시작한다. OWNER/ADMIN/MEMBER만 가능하며 CSRF를 검사한다. 최초 시작은 이슈 version을 확인한다. 연결된 동일 브랜치의 재요청은 이전 응답이 유실됐어도 최신 작업과 함께 반환한다.
- GitHub의 현재 기본 브랜치 SHA를 기준으로 생성한다. 정확히 같은 이름의 브랜치가 이미 있으면 재사용하며 기존 ref를 이동하거나 덮어쓰지 않는다. 동시 생성·타임아웃은 같은 이름을 재조회해 복구한다. 실패·결과 불명에는 작업을 진행 중으로 바꾸지 않는다.
- GitHub 호출 중 DB 트랜잭션/행 잠금을 유지하지 않는다. 성공 후 프로젝트 잠금 안에서 브랜치만 연결하여 그동안 다른 사람이 수정한 본문·담당자 등을 보존한다. 도중에 작업을 보관/완료했으면 연결을 거부하지만 원격에 만든 브랜치를 삭제하지 않는다.
- 준비한 브랜치는 V11의 `work_branch`, `work_branch_base`에 저장하고 새로고침·재로그인 후에도 표시한다. 최초 할 일/백로그는 진행 중으로 이동한다. 열린 PR·병합 PR·명시적 완료·GitHub 닫힘은 기존 PR 상태 규칙을 우선한다. PR 연결을 해제해도 작업 브랜치가 있으면 진행 중으로 돌아간다.
- **Git 명령어 복사**는 해당 저장소의 로컬 폴더에서 실행할 `git fetch origin`과 `git switch feat/{번호}`를 제공한다. 기존 로컬 브랜치가 있으면 그 브랜치로 전환하고, 없으면 Git의 원격 브랜치 자동 연결을 사용한다. 복사가 차단돼도 명령어를 선택해 수동 복사할 수 있다.
- **이 작업으로 PR 작성**은 저장된 작업 브랜치가 현재 GitHub 브랜치 목록에 있으면 미리 선택한다. 이슈도 기존처럼 선택된다. 브랜치만 만들었다면 아직 변경 커밋이 없으므로 로컬 작업·커밋·푸시 후 PR을 만든다.

기존 GitHub 브랜치의 삭제·이름 변경은 자동 추적하지 않는다. `작업 브랜치 확인`을 누르면 원본을 재검증하고 없어진 브랜치는 다시 준비한다. 브랜치 생성에 필요한 GitHub 저장소 쓰기 권한과 조직·브랜치 규칙은 GitHub에서 최종 검증한다.
