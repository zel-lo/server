# 프로젝트 초대와 멤버 관리

갱신: 2026-11-01

프로젝트 설정의 **멤버** 탭에서 실제 서비스 회원과 권한을 관리한다. 프로젝트를 만든 사람은 소유자이며, 프로젝트 전환은 사이드바 상단 메뉴에서만 하며 내부 이슈·멤버·저장소 탭은 같은 현재 프로젝트를 유지한다. **일반** 탭의 이름·설명도 서버에 저장한다.

## 사용자 흐름

1. 소유자/관리자가 참여 권한과 유효 기간을 정해 링크를 만든다. 기본은 MEMBER/3일이며 1시간~7일 범위를 허용한다.
2. GitHub 아이디는 선택 사항이다. 지정하면 GitHub에서 확인한 고정 계정 ID에 묶으며, 아직 zello에 가입하지 않은 계정도 초대할 수 있다. 이름 변경으로 다른 사람이 초대를 가져갈 수 없다. 조직/봇은 초대하지 않는다.
3. 링크를 받은 사람은 GitHub 로그인 후 프로젝트·초대자·권한·만료 시각을 확인하고 **프로젝트 참여하기**를 누른다. 링크 방문이나 미리보기로 가입시키지 않는다.
4. 참여 후 해당 프로젝트의 이슈 화면으로 이동한다. 저장소 접근은 자신의 GitHub 계정 권한으로 별도 검증한다. zello 초대가 GitHub 조직/저장소의 멤버십을 부여하지 않는다.
5. 미사용 초대는 취소할 수 있다. 이미 사용한 링크의 권한 변경/회수는 멤버 목록에서 처리한다. 원문 링크는 생성 응답과 현재 화면에서만 확인할 수 있다. 링크를 잃으면 취소 후 새 링크를 만든다.

공유 링크도 한 사람만 수락할 수 있다. 활성 멤버가 열면 기존 권한으로 이동하며 초대를 소비하거나 권한을 바꾸지 않는다. 사용했던 링크로 나간 프로젝트에 재참여할 수 없고 새로운 초대가 필요하다.

## 권한 정책

| 작업 | 소유자 | 관리자 | 멤버 | 조회자 |
| --- | --- | --- | --- | --- |
| 멤버 목록·검색 | 가능 | 가능 | 가능 | 가능 |
| MEMBER/VIEWER 초대·변경·내보내기 | 가능 | 가능 | 불가 | 불가 |
| ADMIN 초대·권한 관리·내보내기 | 가능 | 불가 | 불가 | 불가 |
| 미사용 초대 목록·관리 이력 | 가능 | 가능 | 불가 | 불가 |
| ADMIN 초대 취소 | 가능 | 불가 | 불가 | 불가 |
| 프로젝트 이름·설명·저장소 관리 | 가능 | 가능 | 불가 | 불가 |
| 이슈·PR 작성/수정 | 가능 | 가능 | 가능 | 불가 |
| 프로젝트 나가기 | 소유권 이전 후 | 가능 | 가능 | 가능 |
| 소유권 이전 | 가능 | 불가 | 불가 | 불가 |

소유자는 `projects.owner_user_id`로 판정한다. 멤버십 role에는 ADMIN/MEMBER/VIEWER만 저장한다. 본인 권한 변경·본인 내보내기·소유자 내보내기는 차단한다. 소유권 이전은 활성 멤버에게만 가능하며 새 소유자는 ADMIN, 기존 소유자는 ADMIN으로 남는다.

멤버를 내보내거나 나가면 `left_at`으로 접근을 종료하고 과거 기록/FK는 보존한다. 재초대로 같은 행을 활성화하며 버전은 초기화하지 않는다. 관리자 권한 하향·내보내기·나가기·소유권 이전 시 해당 사용자가 발급한 미사용 초대를 취소한다. 초대 수락 때 발급자의 현재 활성 상태와 권한도 다시 확인한다.

## API

모든 API는 서버 세션을 요구한다. 변경과 초대 미리보기 POST는 CSRF 토큰이 필요하다. 목록/상세/생성 응답은 `Cache-Control: no-store`다. ID는 JSON 문자열로 반환한다.

| 메서드와 경로 | 요청/동작 |
| --- | --- |
| GET /api/projects/{id}/members | query, page, size / 활성 멤버, 액션 권한, 멤버·프로젝트 버전 |
| GET /api/projects/{id}/invitations | page, size / 토큰 없는 초대 메타데이터·상태 |
| POST /api/projects/{id}/invitations | role, expiresInHours, githubLogin? / 201, 원문 inviteUrl 1회 반환 |
| DELETE /api/projects/{id}/invitations/{invitationId} | 미사용 초대 취소, 이미 취소된 요청은 멱등 |
| POST /api/invitations/preview | token / 제한된 프로젝트 정보, 상태, 수락 가능 여부 |
| POST /api/invitations/accept | token / 명시적 수락 및 참여 프로젝트 반환 |
| PATCH /api/projects/{id}/members/{userId} | role, version / 권한 변경 |
| DELETE /api/projects/{id}/members/{userId}?version=... | 멤버 내보내기 |
| DELETE /api/projects/{id}/membership?version=... | 본인 나가기 |
| POST /api/projects/{id}/ownership | userId, projectVersion, memberVersion / 소유권 이전 |
| GET /api/projects/{id}/membership-history | page, size / 관리 이력 |
| PATCH /api/projects/{id} | version, name, description / 기본 설정 |

멤버 기본 페이지 크기 30, 초대·이력 20이며 최대 100이다. 미사용·미만료 초대는 프로젝트당 최대 20개다. 계정 불일치 403, 찾을 수 없음 404, 동시 변경 409, 만료·취소·다른 사람의 소비 410, 발급 한도 429로 안내한다. 동일 수락자의 성공 재전송은 현재 활성 멤버인 동안만 200을 반환한다.

## 일관성과 보안

- 토큰은 SecureRandom 32바이트(base64url 43자)이며 DB에는 SHA-256 해시만 저장한다. 목록·관리 이력에는 원문/해시를 반환하지 않는다.
- 링크는 `/#/invite/{token}` 형태다. 서버 URL 쿼리에 토큰을 넣지 않고 미리보기/수락 POST 본문에만 전송한다. 초대 상세는 인증 후 지정 계정 검사를 통과해야 볼 수 있다.
- OAuth 왕복은 같은 탭 sessionStorage에 15분간 허용된 `/invite/{43자 토큰}` 경로만 보관한다. 외부 URL·임의 경로는 거부한다. 로그인 콜백에서 소비하고 수락은 다시 사용자가 결정한다. GitHub 토큰은 클라이언트로 전달하지 않는다.
- 모든 멤버십·초대 변경은 프로젝트 행의 비관적 쓰기 잠금으로 직렬화한다. 수락은 READ_COMMITTED에서 프로젝트 잠금 획득 후 초대 행을 다시 읽어 첫 조회 캐시/스냅샷으로 중복 수락하지 않는다. 수락·멤버 반영·감사 기록은 같은 트랜잭션이다.
- 권한 변경/내보내기/나가기에는 `project_members.version`, 소유권 이전에는 프로젝트와 대상 멤버 버전을 함께 요구한다. 오래된 관리 화면으로 새 권한을 덮어쓰지 않는다.
- 선택적 GitHub 계정 확인은 DB 쓰기 트랜잭션 밖에서 수행한다. 조회 전에 관리 권한을 검사하고 실제 저장 시 잠금 안에서 다시 검사한다. GitHub 응답 본문·인증 토큰을 오류 메시지에 포함하지 않는다.
- 사용자 입력을 JSX 텍스트로 렌더링하고 위험 작업은 확인 창과 충돌 복구를 제공한다. 화면의 버튼 표시와 별도로 서버가 권한을 검사한다.

## 마이그레이션과 검증

Flyway V5는 기존 멤버십에 `version BIGINT NOT NULL DEFAULT 0`을 추가하고 초대의 프로젝트별 목록/미사용 조회 인덱스를 만든다. 기존 회원이나 작업을 삭제하지 않는다. 운영 반영 전 DB 백업 후 일반 Flyway 배포 절차로 V1~V5를 적용한다.

자동 검증: H2 API 통합 테스트로 역할 경계, CSRF, 지정 계정, 만료·취소·멱등, 탈퇴/재참여, 소유권 이전, 오래된 버전, 발급 한도와 동시 수락을 확인한다. GitHub HTTP는 MockRestServiceServer로 개인 계정과 안전한 오류 처리를 확인한다. 프런트엔드는 OAuth 복귀, 명시적 수락, 권한별 UI, 버전 전달과 확인 창을 검증한다. ERD SQLite 검증은 제약 논리 검사이며 MySQL 실행 검증과 구분한다.

이번 환경에서 서버 전체 162개, 프런트엔드 전체 95개 테스트와 프런트엔드 빌드가 통과했다. Gradle의 샌드박스 소켓 제약으로 서버는 캐시된 동일 테스트 클래스패스의 javac/JUnit Launcher로 실행했다. 일반 환경의 표준 명령은 `./gradlew test`, 클라이언트는 `npm test` 및 `npm run build`다. 실제 MySQL V5 적용과 서로 다른 실계정의 GitHub OAuth 왕복·초대 참여는 배포 환경에서 추가 확인해야 한다. 이메일/DM 자동 발송은 제공하지 않으며 링크를 복사해 공유한다.
